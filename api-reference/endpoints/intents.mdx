# Intents

Intents are pre-transaction declarations that describe what an agent plans to spend money on. They enable oversight and approval workflows before card credentials are accessed.

## The Intent Object

```json
{
  "id": "int_abc123",
  "cardId": "card_xyz789",
  "intentId": "my-intent-001",
  "purpose": "Purchase office supplies from Amazon",
  "expectedAmount": 5000,
  "expectedCurrency": "usd",
  "expectedMerchant": "Amazon",
  "expectedMccs": ["5942", "5943"],
  "toleranceAmount": 500,
  "tolerancePercent": null,
  "status": "pending",
  "expiresAt": 1705320000000,
  "createdAt": "2024-01-15T10:00:00.000Z",
  "updatedAt": "2024-01-15T10:00:00.000Z",
  "approvedAt": null,
  "rejectedAt": null,
  "rejectionReason": null,
  "canceledAt": null,
  "matchedAt": null,
  "mismatchedAt": null
}
```

### Attributes

| Attribute | Type | Description |
|-----------|------|-------------|
| `id` | string | Unique identifier (prefixed with `int_`) |
| `cardId` | string | ID of the associated card |
| `intentId` | string | Your idempotency key for this intent |
| `purpose` | string | Human-readable description of the spend |
| `expectedAmount` | number | Expected transaction amount in minor units |
| `expectedCurrency` | string | Expected currency code |
| `expectedMerchant` | string | Expected merchant name |
| `expectedMccs` | array | Expected merchant category codes |
| `toleranceAmount` | number | Allowed amount variance (absolute) |
| `tolerancePercent` | number | Allowed amount variance (percentage) |
| `status` | string | Intent status (see below) |
| `expiresAt` | number | Unix timestamp when intent expires |
| `createdAt` | string | ISO 8601 creation timestamp |
| `approvedAt` | string | When intent was approved |
| `rejectedAt` | string | When intent was rejected |
| `rejectionReason` | string | Reason for rejection |
| `canceledAt` | string | When intent was canceled |
| `matchedAt` | string | When intent matched a transaction |
| `mismatchedAt` | string | When intent had a mismatch |

### Status Values

| Status | Description |
|--------|-------------|
| `pending_approval` | Intent requires approval before use |
| `pending` | Intent is approved and waiting to be used |
| `matched` | Intent matched a completed transaction |
| `mismatched` | Transaction completed but didn't match expectations |
| `expired` | Intent expired without being used |
| `rejected` | Intent was rejected |
| `canceled` | Intent was canceled |

## Create an Intent

<div className="api-method-badge">POST</div>

```
POST /v1/cards/:cardId/intents
```

Creates a new spending intent for a card.

### Path Parameters

| Parameter | Type | Description |
|-----------|------|-------------|
| `cardId` | string | The card ID |

### Request Body

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `purpose` | string | Yes | Description of intended spend |
| `intentId` | string | No | Your idempotency key (returns existing if duplicate) |
| `expectedAmount` | number | No | Expected amount in minor units |
| `expectedCurrency` | string | No | Currency code (default: `usd`) |
| `expectedMerchant` | string | No | Expected merchant name |
| `expectedMccs` | array | No | Expected MCCs |
| `tolerance` | number | No | Absolute amount tolerance |
| `tolerancePercent` | number | No | Percentage tolerance |
| `ttlMinutes` | number | No | Time to live (default: 30, max: 1440) |
| `metadata` | object | No | Custom key-value pairs |

### Example

<CodeGroup>
```bash cURL
curl -X POST https://api.useproxy.ai/v1/cards/card_xyz789/intents \
  -H "Authorization: Bearer sk_live_xxxxx" \
  -H "Content-Type: application/json" \
  -d '{
    "purpose": "Purchase office supplies from Amazon",
    "intentId": "my-intent-001",
    "expectedAmount": 5000,
    "expectedMerchant": "Amazon",
    "tolerance": 500,
    "ttlMinutes": 60
  }'
```

```javascript JavaScript
const response = await fetch('https://api.useproxy.ai/v1/cards/card_xyz789/intents', {
  method: 'POST',
  headers: {
    'Authorization': 'Bearer sk_live_xxxxx',
    'Content-Type': 'application/json'
  },
  body: JSON.stringify({
    purpose: 'Purchase office supplies from Amazon',
    intentId: 'my-intent-001',
    expectedAmount: 5000,
    expectedMerchant: 'Amazon',
    tolerance: 500,
    ttlMinutes: 60
  })
});

const intent = await response.json();
```

```python Python
import requests

response = requests.post(
    'https://api.useproxy.ai/v1/cards/card_xyz789/intents',
    headers={
        'Authorization': 'Bearer sk_live_xxxxx',
        'Content-Type': 'application/json'
    },
    json={
        'purpose': 'Purchase office supplies from Amazon',
        'intentId': 'my-intent-001',
        'expectedAmount': 5000,
        'expectedMerchant': 'Amazon',
        'tolerance': 500,
        'ttlMinutes': 60
    }
)

intent = response.json()
```
</CodeGroup>

If the card's policy has `requireApproval: true` and the amount exceeds `autoApproveBelow`, the intent will be created with status `pending_approval` and must be approved before it can be used.

## Reject an Intent

<div className="api-method-badge">POST</div>

```
POST /v1/intents/:id/reject
```

Rejects a pending intent, preventing it from being used.

### Path Parameters

| Parameter | Type | Description |
|-----------|------|-------------|
| `id` | string | The intent ID |

### Request Body

| Parameter | Type | Description |
|-----------|------|-------------|
| `reason` | string | Reason for rejection |

### Example

<CodeGroup>
```bash cURL
curl -X POST https://api.useproxy.ai/v1/intents/int_abc123/reject \
  -H "Authorization: Bearer sk_live_xxxxx" \
  -H "Content-Type: application/json" \
  -d '{
    "reason": "Amount exceeds budget"
  }'
```

```javascript JavaScript
const response = await fetch('https://api.useproxy.ai/v1/intents/int_abc123/reject', {
  method: 'POST',
  headers: {
    'Authorization': 'Bearer sk_live_xxxxx',
    'Content-Type': 'application/json'
  },
  body: JSON.stringify({
    reason: 'Amount exceeds budget'
  })
});

const intent = await response.json();
```

```python Python
import requests

response = requests.post(
```

## Intent Lifecycle

```
Created
   │
   ├── requireApproval: true ──► pending_approval
   │                                    │
   │                         ┌──────────┼──────────┐
   │                         ▼          ▼          ▼
   │                     approved    rejected   expired
   │                         │
   │                         ▼
   └── requireApproval: false ──► pending
                                      │
                         ┌────────────┼────────────┐
                         ▼            ▼            ▼
                      matched    mismatched    expired
                                                   │
                                                   ▼
                                               canceled
```

## Best Practices

1. **Always set a reasonable TTL** - Intents should expire if not used within a reasonable time window
2. **Use intentId for idempotency** - If the same intent might be created multiple times, use intentId to prevent duplicates
3. **Set expectedAmount and tolerance** - This enables transaction matching and mismatch detection
4. **Include purpose** - A clear purpose helps with audit trails and approval decisions
